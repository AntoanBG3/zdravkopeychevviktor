Документът сравнява вариантите за технологичния стек по предварително договорени критерии. Всяко важно решение е записано отделно като ADR в папката [`adr/`](adr/).

## 1. Критерии и тегла

Договорени **преди** оценяването. Сбор: 30 + 20 + 15 + 25 + 10 = **100%**.

| Критерий | Тегло | Какво оценяваме (1 – слабо, 5 – отлично) | Защо това тегло |
|---|---|---|---|
| Опит на екипа | 30% | колко от нас са писали на езика / рамката | Имаме 3 спринта по ~19 точки капацитет; време за учене на нова рамка няма. Затова е най-тежкият критерий. |
| Документация и общност | 20% | официална документация, примери, отговори във форуми | Когато заседнем, документацията и примерите са единствената ни помощ извън часовете. |
| Лиценз и цена | 15% | безплатно ли е за училище, отворен код | NFR-06. Почти всички сериозни варианти са безплатни, затова теглото е по-ниско от опита. |
| Съответствие с изискванията | 25% | покрива ли FR и NFR | Технология, която не покрива NFR-01 или NFR-03, отпада въпреки опита. Второто по тежест. |
| Лесно внедряване | 10% | колко лесно учителят и клиентът стартират продукта | NFR-02. Важно е, но се решава и с избора на база (раздел 3), затова тук е 10%. |

Оставихме теглата от образеца, защото пасват на проекта: уеб приложение с кратък срок и екип, който знае C#.

## 2. Матрица на решенията – уеб рамка

Претеглената стойност е оценка × тегло. Оценките са закръгленото средно на тримата членове.

| Критерий (тегло) | ASP.NET Core MVC | ASP.NET Core Razor Pages | React + ASP.NET Core Web API | Java Spring Boot + Thymeleaf |
|---|---|---|---|---|
| Опит на екипа (0,30) | 5 → 1,50 | 3 → 0,90 | 2 → 0,60 | 1 → 0,30 |
| Документация и общност (0,20) | 4 → 0,80 | 4 → 0,80 | 5 → 1,00 | 4 → 0,80 |
| Лиценз и цена (0,15) | 5 → 0,75 | 5 → 0,75 | 5 → 0,75 | 5 → 0,75 |
| Съответствие с изискванията (0,25) | 5 → 1,25 | 5 → 1,25 | 4 → 1,00 | 4 → 1,00 |
| Лесно внедряване (0,10) | 4 → 0,40 | 4 → 0,40 | 2 → 0,20 | 2 → 0,20 |
| **Общо** | **4,70** | **4,10** | **3,55** | **3,05** |

Проверка на сметките:

- ASP.NET Core MVC: 1,50 + 0,80 + 0,75 + 1,25 + 0,40 = 4,70
- Razor Pages: 0,90 + 0,80 + 0,75 + 1,25 + 0,40 = 4,10
- React + Web API: 0,60 + 1,00 + 0,75 + 1,00 + 0,20 = 3,55
- Spring Boot: 0,30 + 0,80 + 0,75 + 1,00 + 0,20 = 3,05

Аргументи за всеки вариант:

- **ASP.NET Core MVC** – и тримата сме правили MVC проекти с контролери, Razor изгледи и EF Core в училище. Вградени са cookie аутентикация, валидация с атрибути (NFR-03, NFR-04), качване на файлове (US-11) и dependency injection. Работи еднакво под Windows и macOS (NFR-07).
- **ASP.NET Core Razor Pages** – същата платформа, затова покрива изискванията толкова добре, колкото MVC. Губи само по опит: никой от нас не е писал PageModel, а 5 CRUD модула (потребители, роли, екипи, проекти, отпуски) с общ ролеви филтър се подреждат естествено в контролери.
- **React + ASP.NET Core Web API** – най-добра общност, но само един член има опит с JavaScript. Два проекта, CORS и токени вместо cookie правят входа и ролите (US-01, US-14) по-сложни, а стартирането изисква Node.js и build стъпка.
- **Java Spring Boot + Thymeleaf** – покрива изискванията, но никой не е писал Java уеб приложение. Нужни са JDK и Maven, IDE, която не ползваме, и учене на Spring Security от нулата.

Отпаднали преди матрицата:

- **WinForms / WPF** – не са уеб и не работят на телефон и macOS (NFR-01, NFR-07). Заявка и одобрение стават от различни компютри, а настолно приложение би изисквало споделена база по мрежа.
- **.NET MAUI** – за настолни и мобилни приложения, целта е уеб.

### Защо не избрахме втория по точки вариант (Razor Pages)

Разликата от 0,60 идва изцяло от опита на екипа (5 срещу 3 при тегло 0,30). По всички останали критерии двата варианта са равни, защото са една и съща платформа. При 3 спринта и почти пълен капацитет не си струва да учим нов модел на страниците, когато MVC дава същия резултат.

## 3. Сравнение на базите данни

| Критерий | SQLite | SQL Server Express / LocalDB | PostgreSQL |
|---|---|---|---|
| Инсталиране | няма – един файл до проекта | отделен сървър; LocalDB е само за Windows | отделен сървър (или Docker) |
| Работи на macOS (NFR-07) | да | не нативно, само през Docker | да |
| Цена / лиценз | безплатно, public domain | безплатно, с ограничения (размер на базата, памет) | безплатно, отворен код |
| Поддръжка от ORM (EF Core) | да, `Microsoft.EntityFrameworkCore.Sqlite` | да | да (Npgsql) |
| Подходяща за обема данни | да, с голям запас (десетки служители, стотици заявки) | да | да |
| Проверка от учителя (NFR-02) | клонира и стартира | инсталира сървър, настройва connection string | инсталира сървър, създава потребител и база |
| Много потребители едновременно | ограничено (един писател в даден момент) | да | да |
| Прикачени файлове като BLOB (US-11) | да, без проблем при малки файлове | да | да (`bytea`) |

**Решение: SQLite + EF Core с миграции.** Основанието е NFR-02: продуктът се стартира без отделен сървър за база данни; при първото стартиране миграциите се прилагат и началните данни се създават автоматично (`DbSeeder`). Второ основание е NFR-07: SQL Server LocalDB не работи на Mac. Ограничението при едновременни записи не ни засяга: заявките за отпуск са редки и кратки. Подробности в [ADR-002](adr/ADR-002-database.md).

## 4. Проверка на практика (спайк)

Всеки член създава и стартира празен MVC проект на своя компютър:

```bash
dotnet --version
dotnet new mvc -o Spike
cd Spike
dotnet run
```
